Data ingestion

Bridging sources and the platform

What is data ingestion?

Data ingestion is about extracting or capturing data from its source and transporting it to a centralized store, such as a data lake or lakehouse.

data integrationdata collectiondata capture

Other names you will hear for the same thing

The ingestion layer is made of tools that onboard datasets in batch and streaming mode from many data sources.

Solution: the big data ecosystem offers different technologies, each suited to a different ingestion scenario.

How ingestion is done today

Batch / ELT

Extract and load on a schedule; transform later inside the platform.

Airbyte, Fivetran, AWS Glue, Data Factory

Change data capture

Stream every insert, update and delete from a database's log.

Debezium, Datastream, AWS DMS, Qlik Replicate

Event streaming

Applications publish events continuously to a durable log.

Kafka, Kinesis, Event Hubs, Pub/Sub

Zero-ETL

The cloud replicates data between its own services automatically.

Aurora → Redshift, Fabric mirroring

Summary

Which tool for which scenario

Summary

  • Data ingestion is one of the toughest parts of big data: tens of sources, arriving at variable speed and in great variety.
  • We need different technologies depending on the source type and the data velocity.
  • Four scenarios: onboarding, batch, streaming and IoT.
  • Today, CDC and managed connectors dominate batch, and event streaming dominates real time.

Option: Python + Apache Airflow

Airflow 3 runs ingestion pipelines written in Python as DAGs (graphs of tasks).

TriggerSchedule (@daily, cron) or asset update
SensorWait for a file, an object in a bucket or an API
Extract / uploadA Python task reads the source
File storageRaw files in MinIO, S3, ADLS or HDFS

Common sensors

  • FileSensor: a file lands in a folder
  • S3KeySensor: an object appears in a bucket
  • HttpSensor: an API answers

Why choose it

  • Any source you can reach with Python
  • Code in Git, retries, backfills, run history
  • Open source, runs on any cloud

Example: wait for a file, then load it

from datetime import datetime
from airflow.sdk import dag, task
from airflow.providers.standard.sensors.filesystem import FileSensor
from airflow.providers.amazon.aws.hooks.s3 import S3Hook
@dag(schedule="@daily", start_date=datetime(2026, 10, 1), catchup=False)
def sales_files_to_lake():
    wait_for_file = FileSensor(
        task_id="wait_for_file",
        filepath="/data/landing/sales_{{ ds_nodash }}.csv",
        poke_interval=300,          # check every 5 minutes
        timeout=6 * 3600,           # give up after 6 hours
        mode="reschedule",
    )
    @task
    def upload(ds_nodash=None):
        S3Hook(aws_conn_id="minio").load_file(
            filename=f"/data/landing/sales_{ds_nodash}.csv",
            key=f"raw/sales/dt={ds_nodash}/sales.csv",
            bucket_name="datalake", replace=True,
        )
    wait_for_file >> upload()
sales_files_to_lake()

Option: Databricks Lakeflow Jobs

Lakeflow Jobs (formerly Databricks Workflows) orchestrates ingestion inside the Databricks lakehouse.

Files landNew files arrive in cloud storage
TriggerFile arrival, schedule or continuous
Job taskAuto Loader notebook or pipeline
Delta tableBronze layer of the lakehouse
Auto Loader

Incrementally loads new files, remembering which were already processed

Lakeflow Connect

Managed connectors for databases and SaaS apps (SQL Server, Salesforce, Workday…)

Declarative Pipelines

Batch and streaming pipelines in SQL or Python (formerly Delta Live Tables)

(spark.readStream.format("cloudFiles")                 # Auto Loader
    .option("cloudFiles.format", "json")

    .load("/Volumes/main/raw/landing/telegram/")
    .writeStream
    .option("checkpointLocation", "/Volumes/main/raw/_checkpoints/telegram")
    .trigger(availableNow=True)                       # process new files, then stop
    .toTable("main.bronze.telegram_updates"))
How it runs: attach this notebook to a Lakeflow Job with a file-arrival trigger on the landing folder. Each time new files arrive, the job starts, loads only the new files into the Delta table and stops.
