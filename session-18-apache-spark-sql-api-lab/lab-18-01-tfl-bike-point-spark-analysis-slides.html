1.2 Shaping the DataFrame: schema on read

Once your files are in the batch storage layer, your goals are:

  1. Define the logic you need to answer the business questions.
  2. Adapt the "raw" DataFrame into a structure that makes that logic simple: this is schema on read, a powerful way to make the most of the data in your storage layer.
  3. Translate the logic into Spark code: today, much of it in SQL.

"What are the minimum, maximum and average numbers of bikes used during the current month?"

So we need a DataFrame with:

  • the identifier of each bike point and its name;
  • its GPS location (lat, lon), to plot results on a map later;
  • the number of bikes per bike point over time.
Precision: NbBikes counts bikes docked and available at the station, not bikes in use (lab 16.1). We keep the notebook's wording but read it that way.

2.0 Managing temporary views: three functions

FunctionWhat it does
DataFrame.createOrReplaceTempView(name)Creates or replaces a local temporary view with the DataFrame. Its lifetime is tied to the SparkSession that created the DataFrame.
spark_session.catalog.dropTempView(name)Drops the local temporary view from the catalog. The catalog is reached through the session's catalog property.
spark_session.catalog.listTables()Lists the tables and views available in the current SparkSession.

The notebook says "two functions" and then lists three: these three are all you need.

VariantDifference

2.0 Create the BikePoints view

① How many views before anything? 
spark_session.catalog.listTables()
[]
② Create a view called BikePoints from bikepoint_df 
bikepoint_df.createOrReplaceTempView("BikePoints")
③ And after? 
spark_session.catalog.listTables()
[Table(name='BikePoints', catalog=None, namespace=[],
       description=None, tableType='TEMPORARY',
       isTemporary=True)]
  • The empty list [] means a fresh session has no tables or views.
  • createOrReplaceTempView returns nothing and runs no job: it only registers a name in the catalog (you'll see a 0-second entry in the Spark UI).
  • tableType='TEMPORARY', isTemporary=True: it belongs to this session; catalog=None because temp views live outside any database. Spark 4 lists it in lower case ('bikepoints'): names are case-insensitive.
  • Run the cell twice: no error, it just replaces the view. With createTempView the second run would fail with TEMP_TABLE_OR_VIEW_ALREADY_EXISTS.

⚠ Same trap, now in SQL: MIN and MAX of text

value is a string, so MIN and MAX compare alphabetically: "13" < "9". AVG is fine because Spark casts the text to numbers to add it up.

-- how many bike points get a wrong min or max?
SELECT COUNT(*) FROM (
  SELECT id, MIN(value) AS mn, MAX(value) AS mx,
         MIN(CAST(value AS INT)) AS rmn,
         MAX(CAST(value AS INT)) AS rmx
  FROM BikePoints WHERE key = 'NbBikes' GROUP BY id)
WHERE mn <> CAST(rmn AS STRING)
   OR mx <> CAST(rmx AS STRING)
[Row(count(1)=17)]       # 17 of 797 bike points
The fix is the same as in lab 16.1: CAST(value AS INT) before you aggregate.

2.3 Solution: the view and the query

# [TBD 1] a new view for this question
bikepoint_docks_df.createOrReplaceTempView("BikePointsDocks")

# [TBD 2] answer with SQL
broken_df = spark_session.sql("""
WITH totals AS (
  SELECT id, commonName,
    SUM(CASE WHEN key = 'NbDocks'
             THEN CAST(value AS INT) END) AS docks,
    SUM(CASE WHEN key = 'NbBikes'
             THEN CAST(value AS INT) END) AS bikes,
    SUM(CASE WHEN key = 'NbEmptyDocks'
             THEN CAST(value AS INT) END) AS empty_docks
  FROM BikePointsDocks
  GROUP BY id, commonName)
SELECT id, commonName, docks, bikes, empty_docks,
       docks - bikes - empty_docks AS broken,
       ROUND((docks - bikes - empty_docks) * 100.0 / docks, 2)
         AS broken_ratio_pct
FROM totals
WHERE docks - bikes - empty_docks > 0
ORDER BY broken_ratio_pct DESC, id""")

2.3 Reading the answer critically

All London, same 4 snapshots
Available bikes41.1%
Empty docks51.8%
"Broken"7.1%

Of 83,852 dock-snapshots, 5,943 (7.09%) are neither an available bike nor a free dock. 643 of 797 stations (81%) have at least one.

SELECT SUM(docks - bikes - empty_docks) * 100.0 / SUM(docks)
FROM totals          -- 7.09
What does the gap really measure? TfL's tech forum explains that a dock that is out of service is not counted in NbBikes or NbEmptyDocks. So the gap is unavailable docks: a broken bike locked in a dock is one possible cause, a faulty dock is another, and the data can't tell them apart. "Broken-bike ratio" is the notebook's simplification: say so in your report.
Another trap: modified is not a snapshot id. When a station hasn't changed, its modified is the same in several files (562 stations had one value across all 4). To compare snapshots, group by filename_path instead.

Ranking by ratio favours small stations; adding AND docks >= 80 (20 docks × 4 snapshots) is a sensible extra filter.

wide_df = bikepoint_docks_df\

  • Three ways, one plan family, one answer. Use the one your team reads best.
