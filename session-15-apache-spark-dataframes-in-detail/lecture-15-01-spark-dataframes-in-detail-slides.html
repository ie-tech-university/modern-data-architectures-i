Column functions

pyspark.sql.functions, by column type

A rich library of column functions

Beyond column references and operators, pyspark.sql.functions has 428 functions in Spark 3.5 and 507 in Spark 4.1: strings, dates, maths, arrays, JSON…

What you can do depends on the column type. We'll cover the most popular ones; browse the rest in the API reference.

Rule of thumb: if a built-in function exists, use it. It runs inside the JVM and Catalyst can optimise it. A Python UDF can't.

               F.lit(10).alias("scale"),

ratings.select(F.lit(10), F.lit("x"),

| 0.5|  1.0|   0.0|    0.5|     0.5|    0|   1|
| 1.5|  2.0|   2.0|    1.5|     1.5|    1|   2|

FunctionRule
round(c, d)HALF_UP: .5 goes away from zero
bround(c, d)HALF_EVEN ("banker's rounding"): .5 goes to the even neighbour
floor(c)always down
ceil(c)always up
Correction: bround does not round down. On large sums, HALF_EVEN avoids the upward bias of always rounding .5 up: that's why finance uses it.

3.5.6 User-defined functions (UDFs)

import re
from pyspark.sql.types import StringType

# 1. write the function: plain Python
def fix_title(title):
    """Move a trailing ', The/A/An' to the front."""
    if title is None: return None
    title = title.strip()
    m = re.match(r"^(.*), (The|A|An) (\(\d{4}\))$", title)
    return f"{m.group(2)} {m.group(1)} {m.group(3)}" if m else title

# 2. register it so every executor can run it
fix_title_udf = F.udf(fix_title, StringType())       # DataFrames
spark.udf.register("fix_title", fix_title, StringType())  # SQL

movies.select("title", fix_title_udf("title").alias("fixed")) \
      .where("title != fixed").show(4, truncate=False)
+----------------------------------+---------------------------------+
|title                             |fixed                            |
+----------------------------------+---------------------------------+
|American President, The (1995)    |The American President (1995)    |
|Usual Suspects, The (1995)        |The Usual Suspects (1995)        |
|Big Green, The (1995)             |The Big Green (1995)             |
|Indian in the Cupboard, The (1995)|The Indian in the Cupboard (1995)|
+----------------------------------+---------------------------------+

1,554 titles change: 1,543 get their article moved, 11 only lose trailing spaces. UDFs let you write custom transformations in Python (or Scala), take and return columns, and even use external libraries.

Also in SQL: SELECT fix_title(title) FROM movies.

In OSBDET, show() after a Python UDF may print a harmless BrokenPipeError (Spark 3.5 + Python 3.13): Spark stopped reading early. The result is correct.

How a Python UDF runs, and what it costs

The JVM can't run Python. Every row crosses into a Python process and back, and Catalyst sees the UDF as a black box: no pushdown, no optimisation inside it.

Built-in vs UDF vs pandas UDF: measured

x + 1 on 5,000,000 rows · Spark 4.1 local[4] · best of 3
Built-in0.20 s
Python UDF2.87 s
pandas UDF0.90 s
Arrow UDF0.88 s
# vectorised: receives a whole pandas Series per batch
import pandas as pd
@F.pandas_udf("double")
def plus_one(s: pd.Series) -> pd.Series:
    return s + 1.0

# Arrow-optimised plain UDF (Spark 3.5+; default in 4.2)
F.udf(lambda x: x + 1.0, "double", useArrow=True)
  1. Built-in functions first. The title fix above can be done with F.regexp_replace(F.trim("title"), r"^(.*), (The|A|An) (\(\d{4}\))$", "$2 $1 $3"): identical results on all 9,742 titles, no Python.
  2. pandas / Arrow UDFs when you need Python: batches move via Apache Arrow, ~3× faster than a plain UDF here.
  3. Plain Python UDFs last: simplest, slowest.
Always declare the return type, and handle None inside the function: NULLs reach your Python code as None.

Summaries, groups and pivots

Summarising DataFrames: group, then aggregate

Aggregation functions (UDAFs) produce one result per group: count, sum, avg… all in pyspark.sql.functions.

Grouping options in Spark

ΣSummarise

No grouping: one row for the whole DataFrame.

df.select(F.avg(…))
df.agg(…)

🗂Groups

One row per value of one or more columns.

groupBy(…).agg(…)

🧮Multi-level

pivot (today), rollup, cube (subtotals).

groupBy(…).pivot(…)

🪟Windows

Aggregate without collapsing rows: rankings, running totals.

F.row_number().over(w)

Rollup, cube, windows and user-defined aggregate functions aren't covered in depth in this course; you'll get a quick peek at the end of this section.

3.7

Joins

Combine DataFrames from anywhere

Joins: data federation

A join combines a left DataFrame with a right one, wherever each comes from and whatever its format. That's possible because every source is abstracted as a DataFrame, which gives:

  • a common format (relational: rows and columns), and
  • one set of functions for transformations and aggregations.

Rows are combined by comparing keys on both sides and evaluating a join expression, most often an equality: ratings.movieId == movies.movieId.

Two ways Spark executes a join

Spark picks the strategy: see it with explain()

ratings.join(movies, "movieId").explain()
+- BroadcastHashJoin [movieId], [movieId], Inner, BuildRight
   :- FileScan csv ratings …
   +- BroadcastExchange HashedRelationBroadcastMode(…)
      +- FileScan csv movies …

movies (~0.5 MB) is under spark.sql.autoBroadcastJoinThreshold (10 MB by default), so Spark broadcasts it automatically.

# force it when Spark can't estimate the size
ratings.join(F.broadcast(movies), "movieId")
spark.conf.set("spark.sql.autoBroadcastJoinThreshold", -1)
ratings.join(movies, "movieId").explain()
+- SortMergeJoin [movieId], [movieId], Inner
   :- Sort [movieId ASC NULLS FIRST]
   :  +- Exchange hashpartitioning(movieId, 200)
   :     +- FileScan csv ratings …
   +- Sort [movieId ASC NULLS FIRST]
      +- Exchange hashpartitioning(movieId, 200)
         +- FileScan csv movies …

With broadcast disabled: a shuffle (sort-merge) join. Both sides are shuffled by key (Exchange) and sorted. Adaptive Query Execution can still switch to broadcast at runtime if one side turns out to be small.

Join types

innerdefault · matches only
left · left_outerall of A, NULLs where B is missing
right · right_outerall of B, NULLs where A is missing
full · outer · full_outereverything from both
left_semirows of A with a match · A's columns only
left_antirows of A without a match · A's columns only

df.join(other, on, how): on is a column name, a list of names or a join expression; how defaults to "inner". Also cross (every row with every row; crossJoin()). There is no right_anti: swap the DataFrames and use left_anti.

Join gotchas and real questions

Same column name on both sides 
j = m.join(r, m.movieId == r.movieId)   # expression
j.columns       # ['movieId', 'title', 'movieId', 'rating']
j.select("movieId")
AnalysisException: [AMBIGUOUS_REFERENCE] Reference `movieId` is ambiguous, could be: [`movieId`, `movieId`].
  • Join on the name ("movieId" or a list): one key column in the result.
  • Or say which one: j.select(m.movieId, "title", "rating"), or use m.alias("a") + F.col("a.movieId").

3.8

Sets and sampling

union, intersect, except, sample, randomSplit

Union: by position or by name?

x = spark.createDataFrame([(1, "Toy Story")],
                          "movieId INT, title STRING")
y = spark.createDataFrame([("Jumanji", 2)],
                          "title STRING, movieId INT")

x.union(y).show()          # by POSITION 😱
x.unionByName(y).show()    # by NAME ✓
+-------+---------+
|movieId|    title|
+-------+---------+
|      1|Toy Story|
|Jumanji|        2|
+-------+---------+
+-------+---------+
|movieId|    title|
+-------+---------+
|      1|Toy Story|
|      2|  Jumanji|
+-------+---------+
  • union (and its alias unionAll) stacks rows by position and keeps duplicates (SQL UNION ALL). Add .distinct() for SQL UNION.
  • Different column order → silently wrong data (here an ID became "Jumanji").
  • unionByName matches columns by name. With allowMissingColumns=True it fills missing columns with NULL.
  • Different number of columns with union: [NUM_COLUMNS_MISMATCH] error.
Prefer unionByName whenever the DataFrames come from different sources.

a = ratings.filter("userId = 1").select("movieId")   # 232

a.union(b).distinct().count()   # 263

Sampling: sample and randomSplit

# sample(withReplacement=False, fraction, seed=None)
ratings.sample(fraction=0.1, seed=1).count()   # 10017
ratings.sample(fraction=0.1, seed=2).count()   # 10181
ratings.sample(fraction=0.1, seed=3).count()   # 10064
ratings.sample(True, 0.1, seed=42).count()     # 10140
  • fraction is a probability per row, not an exact size: ~10%, never exactly 10,084.
  • withReplacement=True: a row can be picked more than once.
  • Same seed + same data and partitioning → same sample.
train, valid, test = ratings.randomSplit(
    [0.7, 0.15, 0.15], seed=42)
train.count(), valid.count(), test.count()
# (70549, 15090, 15197)  → 100836 in total
train · 70,549
valid · 15,090
test · 15,197
  • Splits every row into exactly one part; weights should add up to 1 (otherwise they're normalised).
  • The classic use: train / validation / test sets for machine learning.
3.9

Null handling

Missing data, done right

NULL: missing data, with its own logic

  • NULL represents missing or empty data. Spark optimises it, so prefer NULL over empty strings or magic values like −1.
  • Handling nulls matters most in machine learning: many algorithms can't deal with them.
  • Where they come from: missing values in the source, and outer joins.
Found in MovieLensNULLs
links.tmdbId8 movies without a TMDB id
movies ⟕ avg rating18 movies (never rated)
Comparisons with NULL give NULL, not false 
q = spark.createDataFrame([(None,), (1.0,)], "v DOUBLE")
q.select("v",
    (F.col("v") == F.lit(None)).alias("eq_null"),
    F.col("v").isNull().alias("isNull"),
    F.col("v").eqNullSafe(None).alias("eqNullSafe")).show()
+----+-------+------+----------+
|   v|eq_null|isNull|eqNullSafe|
+----+-------+------+----------+
|NULL|   NULL|  true|      true|
| 1.0|   NULL| false|     false|
+----+-------+------+----------+
q.filter(F.col("v") != 1.0).count()   # 0 (!)
# NULL != 1.0 is NULL, so that row is dropped too

Never test with == None: use isNull() / isNotNull(), or eqNullSafe (SQL <=>).

Detect NULLs

avg = ratings.groupBy("movieId").agg(
    F.round(F.avg("rating"), 2).alias("avg"),
    F.count("*").alias("n"))
mv = movies.join(avg, "movieId", "left")     # creates NULLs

mv.filter(F.isnull("avg")).select("title", "avg", "n").show(3)
# same as .filter(F.col("avg").isNull())

# count the NULLs of every column in one pass
mv.select([F.sum(F.col(c).isNull().cast("int")).alias(c)
           for c in mv.columns]).show()

Fix NULLs: fillna, coalesce, dropna

fillna(value, subset): "fill not available" 
(mv.fillna(0, subset=["n"])          # one value, some columns
   .fillna({"avg": -1.0})              # or a dict per column
   .filter("n = 0").show(3))
# Innocents, The (1961) | -1.0 | 0 …

# coalesce: first non-NULL value, per row
mv.select("title", F.coalesce("avg", F.lit(0.0)))
  • Value must be int, float, bool or string; it only fills columns of a matching type.
  • Also df.na.fill (same), df.na.replace for non-NULL values.
dropna(how="any", thresh=None, subset=None)
Call on mv (9,742 rows)Rows left
dropna() · any NULL9,724
dropna(how="all")9,742
dropna(subset=["avg"])9,724
dropna(thresh=4) · ≥ 4 non-NULL9,724
  • how="any" drops a row with any NULL; "all" only if every value is NULL.
  • thresh overrides how: keep rows with at least n non-NULL values.
Fill or drop? Dropping loses rows; filling with 0 can bias averages. Decide per column, and document it.
